# 默点啥 mds — 实施报告

日期：2026-08-01

## 需求

极简默写辅助工具：单词列表 → 预生成语音（edge-tts）→ 按计算节奏逐词播报（书写/赛博两模式）→ 结果对照批改。目标产物：Windows 免安装可执行程序（deno desktop）。详见 AGENTS.md「系统基础功能」。

## 关键决策

| 决策点 | 选择 | 原因 |
| --- | --- | --- |
| 包管理/工具链 | pnpm 管依赖与 vite 构建，deno 负责 `deno desktop` 运行与 Windows 打包 | 用户确认；SolidStart 生态是 npm 的，deno 只在打包层介入 |
| 每轮时长 | `max(字母数×0.45s×档位, 音频时长×遍数+间隙) + 1.5s`，释义模式加 `释义词数×0.5s`，整体 ×倍率调整 | 用户确认数值；音频时长为准备阶段 webview 实测值，非估算 |
| 播报遍数 | 释义模式 3 遍；非释义 <6 字母 2 遍、≥6 字母 3 遍 | AGENTS.md 规则 |
| 跳转解耦 | 倒计时结束/语音播完各自打标记，双标记齐才进下一轮；赛博模式未提交单词时**等待输入**（时间到会提示，避免打字被切断） | AGENTS.md 解耦规则 + 赛博 UX 安全网（报告中记录此追加） |
| 对错判断 | 仅赛博模式；严格匹配（trim 后大小写/标点/空格完全一致）；释义不批改 | 用户确认 |
| TTS 库 | `edge-tts-universal`（npm），**跑在服务端**（Nitro server route） | v1.4.0+ 浏览器环境（除 Edge）无法连 Microsoft TTS，Deno/Node 服务端不受影响；已冒烟验证 Deno 下合成成功 |
| 语音缓存 | `voice-cache/`（可执行文件同目录），文件名 = 转义词 + 6 位 FNV 哈希，增量命中 | AGENTS.md 要求按词缓存、文件名转义 |
| AI 释义 | 服务端一次调用 OpenAI 兼容接口返回全部单词 JSON 英文释义；5 类错误码（no-config/http/network/timeout/invalid-response/empty） | 避免 CORS、key 不落前端 |
| 路由 body 解析 | SolidStart 2 路由事件是 rou3 风格（`event.request`/`event.params`），**不能直接用 h3 readBody**（其读 `event.req`） | 实测踩坑，自写 `lib/server-body` |
| 设置存储 | localStorage（webview profile） | AGENTS.md 指定 |
| dev 端口 | 固定 5199（strictPort） | 避免与 vue-admin 的 5173 冲突 |

## 结果

- **界面**：`.design/mds.pen` 设计 6 屏（词库/准备中/准备完成/默写中/结果/设置），浅灰底+白卡+青绿主色+金黄星星（呼应图标），视觉模型逐屏验证无布局问题
- **后端 API**（实测通过）：
  - `POST /api/tts`：合成+缓存，并发 2，支持中止（请求 signal）
  - `GET /api/audio?name=`：mp3 服务，文件名校验（非法 400/缺失 404）
  - `POST /api/definitions`：真实调用成功（minimax OpenAI 兼容端点，9.8s 返回儿童友好英文释义），错误路径全测
- **单测**：35 个全绿（timing/match/state/tts-filename 四模块）
- **构建**：`pnpm build`（node-server）与 deno desktop 内部构建（deno-server preset）均通过
- **Windows 打包**：`deno desktop --no-check --target x86_64-pc-windows-msvc -P --output ./dist/mds-windows --icon ./public/icons/app.ico .` → `mds-windows.exe`（PE32+ GUI）+ `mds-windows.dll`（265MB，含运行时+VFS）+ `AppIcon.ico`（自绘金星，7 尺寸）

## 踩坑记录（供后续参考）

1. **h3 版本/事件不兼容**：SolidStart 2 + nitro 3 beta 的路由事件是 rou3 风格，h3 的 `readBody`/`getRouterParam` 不适用（读 `event.req` 而事件只有 `event.request`）→ 自写解析
2. **dev 模式路由注册**：新增/修改路由文件需重启 vite dev 才生效；`[name]` 动态段路由在 dev 下 404（生产正常）→ 音频路由改用查询参数形式
3. **deno desktop 交叉编译**：`--target windows` 时 output/icon 按宿主平台（linux）配置选择 → 用 `--output`/`--icon` CLI 参数强制
4. **deno 类型检查误报**：对 nitro 打包产物的动态导入报 TS2307（node 下运行正常）→ `--no-check`
5. **deno.json app.name 仅 ASCII**：中文名校验失败且校验发生在打包后（会先写出中文产物）→ name 用 `mds`，窗口标题走 HTML `<title>`；中文产物已清理并 gitignore 兜底
6. **dev 端口**：vite dev 默认 5173 与 vue-admin 冲突 → 固定 5199

## 补充：业务逻辑审查 + 边界测试（2026-08-01 晚）

### 审查发现并修复的真 bug

1. **超长单词缓存文件名超限**：escapeWordForFilename 不截断 → 90+ 字母单词文件名 >80 字符 → 音频路由正则拒绝（400）→ 音频无法播放。修复：转义后截断 40 字符（哈希保证唯一）。
2. **全角/非 ASCII 字符穿透转义**：toLowerCase 后全角字符仍是全角，`[^a-z0-9]` 只剔 ASCII → 全角文件名过不了音频路由校验。修复：先剔非 ASCII（`[^\x00-\x7F]` → `_`）。
3. **canAdvance 未定义轮返回 undefined**：`{} .countdownDone && ...` 返回 undefined 而非 false。修复：`!!` 强制布尔。
4. **requestTtsAll 空数组防御**：words=[] 时提前返回（前端已拦截空词库，双保险）。
5. **settings voice 校验**：localStorage 里无效 voice 现在回退默认（此前直接透传会导致 TTS 失败）。
6. **abortPreparation 清空 rounds**：中止后不留旧轮次数据。

### 审查确认无需改动的设计点

- 赛博模式 countdown 结束强制提交（含空释义）— 符合"时间一到直接提交"需求
- 书写模式空格跳轮（仅音频未发声时）— 符合需求
- 双轨制 advance 条件（speechDone 必须，赛博 inputDone 可提前）— 符合需求

### 测试覆盖提升

42 → 77 用例（+35 边界）：timing（混合字符/超长/倍率极值/空释义/6字母边界）、match（空白/全角/换行/undefined）、state（空列表/原数组不变/未定义轮/大小写严格）、tts-filename（超长截断/全角/空voice/截断后哈希区分）。
