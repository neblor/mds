# 中文词默写模式 + 可滑动选择条 + 结果页通用化

## 需求

1. 新增「中文对应词」默写模式：准备阶段由 AI 抓取每个英文单词的常用中文词（如 `hello` → `你好`，是词不是释义），流程与单词模式一致，仅最终判定按中文词匹配度
2. 把「默写释义」开关换成可滑动、可扩展的选择条组件，提供三种默写内容：单词 / 释义 / 中文词
3. 评估中文词数据是否单独建 JSON 缓存文件
4. 结果页通用化改造：每种模式下「批改部分」与「仅供参考部分」（如释义对照）展示更合理、可扩展
5. 顺手美化全对时的星星庆祝动画

## 关键决策

### 中文词缓存：独立文件 `chinese-words.json`

选择**独立文件**而非并入 `definitions.json`。理由：

- 两类数据相互独立：一种缓存损坏、格式演进或清空不影响另一种
- 单文件体积增长会把「释义很长」与「中文词很短」的数据耦合，读写放大
- 写入失败/坏缓存时可独立降级
- 代价几乎为零：沿用同一套原子写（临时文件 + rename）与模型版本化校验

实现上把 `RuntimeCacheStorage` 扩展出 `readChineseWords/writeChineseWords`，与释义共用 JSON 原子写工具函数。

### AI 提供器泛化（definition-provider）

`fetchEnglishDefinitions` 泛化为 `fetchAiPairs({ kind })`，新增 `fetchChineseWords`：

- 提示词按 kind 区分；中文词要求返回 `{"words": {...}}` 形状，简体中文、无拼音
- 校验按 kind 区分：释义要求非汉字；中文词**必须包含汉字**（过滤 AI 误返回英文/拼音）
- 保留 `fetchEnglishDefinitions` 原签名与结果形状，既有路由、诊断脚本、测试零改动

### 通用词条编排（ai-pair-service）

把释义服务 `definition-service` 的「缓存命中 → 第三方请求 → 校验合并 → 原子缓存与复读验证」抽成按 kind 参数化的通用编排 `getAiPairs`；`definition-service` 与新增 `chinese-word-service` 都只是薄包装，保持各自导出形状。生产实际调用的是通用编排，测试覆盖同一实现。

### 结果页通用模型（results.ts）

弃用原来写死的「单词对错 + 释义对照」结构，改为声明式字段模型：

- `ResultRow { word, audioName, fields[] }`，每个字段有 `kind`（word/definition/chinese）、`expected`、`userValue`、`graded`、`correct`
- 单词/释义模式：判定 = 单词（严格匹配）；释义 = 参考字段（含「我的释义」），不批改
- 中文词模式：判定 = 中文词（归一化匹配：忽略空白与中文标点，如 `你好！` ≈ `你好`）；英文单词是题干
- 书写模式：无判定，只展示参考（释义/中文词标准）供自检
- 判定说明文案也按模式化（`JUDGEMENT_NOTES`）
- 中文词标准行固定展示在左侧供对照，作答在右侧上色，与单词模式视觉一致

### 选择条组件（SegmentedSlider）

通用组件 `SegmentedSlider`：任意字符串选项数组（可带 Lucide 图标），点击、左右拖拽、方向键/Home/End 均可切换；滑块用 `translateX(索引×100%)` 平滑滑动，拖拽期间禁用过渡跟手，纯计算逻辑 `indexAtPointer` 独立成可单测的纯函数。键盘铁律：radiogroup 语义 + 方向键连续操作。

### 中文词书写时长

倒计时沿用单词模式公式，但作答段按汉字数计：`(思考2 + 0.8×汉字数) × 播报遍数`（写汉字比字母慢）。播报遍数仍按单词长度（与单词模式一致）。

### 全对庆祝美化

从单排 6 颗星改为两波共 13 颗星（不同大小/延迟/水平漂移/旋转）+ 中心 Sparkles 弹性弹跳 + 顶部柔光；星星上浮时带闪烁（外层 translate 动画 + 内层 scale 闪烁双动画，互不干扰）。CSS 变量控制每颗星的漂移/缩放/旋转/时长。

### 持久化与兼容

- 旧 `mds.withDefinition.v1` 开关键迁移：`"1"` → `definition`，`"0"` → `word`（仅在新键缺失时读取）
- 新键 `mds.contentMode.v1` 保存 `word|definition|chinese`

### 其他

- `/api/chinese-words` 路由镜像 `/api/definitions`（参数校验、错误码、诊断日志）
- 客户端 `requestChineseWords`；`pnpm get:explain --chinese ...` 支持中文词诊断
- `timedOutInputPatch` 按 contentMode 决定是否封口释义字段；赛博中文词模式只有一步输入
- 设置面板文案更新；README/.design 文档同步

## 设计说明

本任务涉及界面改动，按 AGENTS.md 应先建 `.pen` 设计文件，但本会话无 pencil MCP 工具可用（`.pen` 为加密文件仅能通过 MCP 操作），因此直接沿用项目既有设计令牌与同类实现（速度三档分段控件、surface/soft/brand 色彩、圆角体系），并把选择条做成与既有速度控件同风格的组件。AGENTS.md 也规定与已有实现同方向的细节以现有实现为准。

## 测试与验证

- 单元测试 257 个全部通过（新增约 60 个）：`segmented-slider` 拖拽数学、`isChineseMatch` 归一化、中文词时长、中文词 provider（含 20 词回归、汉字过滤、数组/代码块解析）、`chinese-word-service`（20 词批量、缓存命中、模型失效、写失败降级、部分返回）、`/api/chinese-words` 路由（部分缓存策略、原型键过滤、无 JSON 继续）、`results` 字段模型、`use-dictation` 中文词流程（准备/单步输入/判定/书写参考/未配置 AI 拦截）
- `pnpm check` 全绿（测试 + 生产构建 + HTTP 冒烟）
- Playwright headless 全流程人工冒烟通过：滑块点击/键盘/拖拽切换与持久化、中文词模式全流程（含全对 13 星庆祝、2/2 计数、判定说明）、释义模式两步输入与「我的释义」对照、书写模式空格跳轮、Escape 关闭、清空

## 后续可处理

- 中文词多义选择：当前 AI 只取最常用一个词，如需要可支持多个候选并做模糊匹配
- 结果页中文词「标准行」固定展示，也可考虑只在答错时展示以减少信息量（当前信息量更利于对照学习）
- SegmentedSlider 已支持任意选项，未来加更多默写内容模式无需改组件

## 布局微调（同轮反馈）

- 移除「默写内容」文字标签；速度三档与内容选择条合并为一行、靠左排列、间隔 12px
- 选择条不再占满整行，改为固定宽度；组件根类不再默认 `w-full`，宽度由调用方通过 `class` 指定，保持组件通用性
- 高度统一：控制行去掉 `items-center`，改用默认 `items-stretch` 拉伸；滑块根类 `h-9` 改为 `min-h-9`，两条像素级等高（实测均 43.5px），且随字体/内边距变化自动保持一致
- 宽度按内容实测计算：三个选项内容（图标+文字）最宽 63px（中文词），按每侧 ≥12px 留白 → 槽宽 93px → 总宽 288px（`w-72`）；实测各槽留白 15–21.5px、无溢出
- 验证：两条等高、留白达标、点击/拖拽/键盘切换正常

## 切换动画修正（同轮反馈）

- 问题：指针按下瞬间滑块直接跳到目标槽位（拖拽态禁用过渡），点击/拖拽切换看起来是瞬移；只有载入恢复记忆选项时有动画
- 修复：按下时不再移动滑块；指针位移超过 6px 阈值才进入跟手拖拽，纯点击在抬起时提交，由过渡动画平滑滑过去
- 防悬停误判：未按下时的 pointermove 一律忽略（此前悬停移动会被当作拖拽起点）
- 不能依赖按钮 click 事件提交（指针捕获会把 click 重定向到轨道容器），点击提交在 pointerup 中按抬起位置完成
- 验证：点击/键盘/拖拽切换与刷新恢复全部通过（点击与键盘均在 60ms 采样到中间位置证明有过渡动画）
