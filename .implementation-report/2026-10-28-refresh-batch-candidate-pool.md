# 重新取词固定返回同一批：候选池抽样与必变约束（2026-10-28）

> **已被取代（2026-10-28 同日修订）**：本报告的 `avoid` 方案会与后续确定的「必默前缀」冲突，
> 最终实现改为「100 候选池 + 前 K 个必默 + 其余随机」，见
> `2026-10-28-mandatory-prefix-batch-selection.md`。本文件仅保留为第一次排查与修复过程记录，
> 不要按这里的 `avoid` 接口理解当前代码。

## 问题与根因

「重新取词」在不作答、卡片状态不变的情况下反复点击，词面完全不变。

整条按钮接线实际是通的：`TodayQueueCard` 调用 `useWordBanks.refreshQueue()`，前端请求 `/api/review-queue`，服务端重新执行 `buildQueueForBank()` 并调用 `setQueue(view)` 替换当前队列。根因在 `buildRoundQueue()`：

- 到期复习按 `due` 稳定排序，新词按词频/词表顺序稳定排序；
- 随后直接 `slice(0, size)`；
- 因此输入卡片状态没变时，每次必然返回相同的前 N 个词，随机性、换批语义和备选词都不存在。

2026-10-24 的实施只实测了「练完一批后，卡片状态改变，再取下一批」，没有覆盖「未作答直接连续换批」，所以测试全绿仍漏掉这个问题。

修复前新增的回归用例（120 个新词，每批 30，第二次带上一批避开词）实测失败：第二次仍包含上一批首词且完整词面相同；其余 853 条测试通过。

## 修复方案

### 1. 推荐排序与最终选词分离

`src/lib/round-queue.ts`：

- 保留既有候选资格与排序：只取 `due <= now` 的复习词和未学新词；复习按逾期程度、新词按词频排序。
- 排序结果只用来形成最多 100 个词的候选池，不再直接固定截取前 N 个。
- 使用 Fisher–Yates 洗牌后无放回抽取 `size` 个；输出仍按复习、新词分组，复习词显示在前。
- `QUEUE_CANDIDATE_POOL_SIZE = 100`；`shuffleFn` 可注入，生产随机，测试可精确锁定候选池边界。

### 2. 换批不是“赌随机碰巧不同”，而是有保证的变化

- 客户端同库刷新时取上一批首词，作为 `avoid` 查询参数传给服务端。
- 候选总数大于本批名额且避开词仍在候选中时，先排除该词再组成 100 词候选池。
- 因为上一批首词不可能再次入选，所以新批至少有一个词不同；其他词允许重叠。
- 备选总数不超过名额时不应用避开规则，仍返回全部词，不能为了制造变化而减少队列。
- 初次选库/首次拉取没有上一批，不传 `avoid`。

### 3. 请求与响应链路

- `use-wordbanks.ts`：同库 `refreshQueue()` 传上一批首词；响应仍整体替换 `queue` 并清空 `batchDone`。
- `bank-api.ts`：`fetchReviewQueue(bankId, size, avoidWord?)`；增加 `cache: "no-store"`，防止旧队列被 HTTP 缓存重放。
- `routes/api/review-queue.ts`：读取 `avoid` 并传入生产服务。
- `review-service.ts`：把 `avoidWord` 传入 `buildRoundQueue()`；释义表按新队列重新生成。
- 换批仍只读卡片和统计，不写 FSRS 状态，不改每日统计口径。

## 回归测试

- `round-queue.test.ts`：
  - 120 词取 30，未作答直接换批必须排除上一批首词且词面不同；
  - `avoidWord` 走统一 `wordKey` 归一；
  - 抽样只能来自优先级最高的 100 个候选，第 101 个及以后不能在无避开词时跃入；
  - 备选不足时保留全部词；
  - 旧排序测试通过注入固定洗牌，继续独立验证候选资格和排序。
- `review-service.test.ts`：服务层实际传递 `avoidWord`，换批后队列和英文释义同步更新。
- `use-wordbanks.test.ts`：首次请求无 `avoid`，同库第二次请求带上一批首词和 `no-store`，并用响应替换当前队列。
